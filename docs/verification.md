## Единая локальная команда

`python tools/verify-local.py` запускает существующий короткий набор: JS/HTML-связи и синтаксис, согласованность документов, Git/SHA снимков, инициализацию мира, механизмы и `git diff HEAD --check` (staged и unstaged). Исполнитель — [tools/verify-local.py](../tools/verify-local.py). Python используется тот же, которым запущен скрипт; Node берётся из PATH или встроенного runtime Codex. При другом расположении Node можно указать переменную `BIG_EVOLUTION_NODE`.

Для текущего ПК без Python в PATH: `& 'D:/Programs/anaconda3/python.exe' tools/verify-local.py` из корня проекта. Скрипт сам выбирает корень по своему пути, поэтому допускает также запуск по абсолютному пути из другого каталога.

После локального исправления можно повторить часть: `--only docs` (ссылки, бюджет контекста, git diff), `--only static` (все статические проверки), `--only startup`, `--only worker` или `--only mechanisms`. Перед завершением нужен подходящий итоговый прогон; повтор после новой ошибки полезен и разрешён. Ошибка или превышение 60 с на одном этапе останавливает набор с ненулевым кодом; оставшиеся этапы не выдаются за пройденные. Длительности и stdout/stderr сохраняются в `.transfer/verification-latest.json`, механизмам соответствует отдельный `.transfer/mechanisms-latest.json`. Исторический первый полный прогон: 11,65 с, шесть этапов, 207/207 механизмов; это не новый результат 0.38.0.

Архивы, снимки, коммиты, установка зависимостей, HTTP-сервер и публикация не запускаются этой командой. Длинные опыты/полная серия замеров не входят в короткий набор. Проверки Node не подтверждают настоящее отображение браузера или работу браузерных Worker.

## Существенные свойства

- Один seed и настройки воспроизводят состояние независимо от разбиения шагов и отрисовки.
- Пища и энергия учитываются через усвоение, насыщение, рождение и гибель.
- Невидимые изменения не влияют на наблюдения или выбор до нового восприятия.
- Геном за жизнь не переписывается; ребёнок не наследует memory/longMemory/recentEvents/experience/weights/traces.
- При одинаковом геноме, теле, памяти и локальной обстановке перенос не меняет вероятности.
- Временные коллекции и численные параметры ограничены, вероятности конечны.
- Совместимость старого генома проверяется отдельно от нового формата.
- В тестовой фикстуре после ручной смены генов traits надо пересоздать через createBrain: они вычисляются при рождении и кэшируются.

Управляемые полезные/вредные оценки в тестах — фикстуры, не настройки основателей игры. Отпечатки прежних источников проверяются по sourceTemplate, а основателей — по позициям и первым 450 генам; новые четыре гена используют отдельный RNG.

## Что не доказывает прохождение тестов

Полезность обучения для популяции, возникновение человечества, устойчивость в ещё не существующем кризисе, визуальную корректность настоящего браузера. Среднее чувство и число живых сами по себе не доказывают качество обучения. Базовые числа длинных опытов относились к карте 24×16, их не выдавать за опыт расширенной карты.

## Сохранение и публикация

1. Для разрешённого изменения Site следовать актуальному Sites skill, открыть существующий репозиторий.
2. Получить короткоживущий Git credential, хранить только в памяти и передавать helper через stdin.
3. Проверить изменения и регенерировать каталог исходников; generated source-files, source-manifest.json и zip руками не редактировать.
4. Source helper фиксирует/push исходники и упаковывает соответствующий архив. Передавать native tools его project_id, commit_sha и archive без подмены.
5. Получить актуальный audience/access. Сохранять действующую аудиторию и список доступа. Для публичной/разделяемой аудитории — save_site_version и deploy_site_version; owner-only операции только для подтверждённого owner-private состояния.
6. Проверять статус только до терминального результата; не делать повторную публикацию после успешной.
7. Если браузерная проверка недоступна, назвать предел проверки. Не расширять доступ ради теста.

Managed preview допускается только через поддерживаемый control-browser, если он доступен. TinyFish для приватного сайта требует вход именно в лабораторию в сохранённом профиле; вход в сам TinyFish не подтверждает такой доступ.
