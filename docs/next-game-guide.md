# Контракт: пособие во вкладке «О проекте»

Статус: структура и стиль выбраны. Пособие приоритетно: дерево/отдельная статья и многослойный текст; визуальная карта отложена. [Технические исправления 0.53.3](updates/v053-live-statistics.md) выполнены; первый подраздел пособия — следующий отдельный этап.

## Цель и принятые требования

Пользователь хочет как можно полнее описать действующие механики и их связи, сделать ссылки между частями пособия и обновлять описание при каждом выпуске. Описание — приоритетная работа из нескольких патчей. Работать по карте проекта и главам, чтобы не перечитывать весь код при каждой правке. Новые игровые правила этим запросом не разрешены.

Уточнение пользователя: вкладку назвать «О проекте». Слева — оглавление в виде дерева ссылок: части → подчасти → конкретные механики. Содержимое добавлять небольшими подпатчами: одна достоверно проверяемая тема или несколько тесно связанных пунктов, умещающиеся в рабочий контекст. Прежде всего выбрать структуру вкладки и стиль текста; первоначальная разбивка на три крупных патча ниже теперь только тематическая группировка, а не фиксированный размер выпусков.

## Варианты для выбора

Выбор пользователя: дерево слева и отдельная статья справа; стиль многослойный — простое объяснение, пример, раскрываемые точные правила. Визуальная карта справочника отложена до отдельного обсуждения; не создавать её в первом патче. Варианты ниже сохранены как история выбора. Пособие дальше пополнять небольшими проверенными подразделами.

Все варианты сохраняют дерево слева. (1) Дерево и отдельная статья справа: выбор листа показывает завершённый подраздел, родителя — обзор ветки; предлагается как основа. (2) Дерево и непрерывная страница раскрываемых разделов: ссылки прокручивают к пункту, соседние темы доступны одновременно. (3) Дерево и обзорные карточки/схемы ветки: справа сначала связи механик и карточки, затем выбранная статья; больше визуальных ориентиров, больше работы интерфейса. Это предложения, не выбранная реализация.

Стили: (а) объясняющий — короткие связанные абзацы и примеры без обязательных формул; (б) строгий справочник — определения, состояния, единицы, условия, расчёты и крайние случаи; (в) многослойный — сначала понятное объяснение, затем подробная механика/пример и раскрываемые точные правила/ограничения. Рекомендация агента — (1)+(в), с общим словарём терминов. Для всех стилей факты проверять по коду, гипотезы маркировать, не очеловечивать алгоритм как доказанную стратегию.

Предлагаемые ветки: введение/управление; мир/среда; житель/действия/сведения/память; мозг/предпочтения/обучение/цена; размножение/наследование/эволюция; опыты/статистика; файлы/производительность; развитие/ограничения. Дерево отражает вложенность тем, перекрёстные причинные связи — отдельными ссылками/схемами внутри статьи. Стрелка раскрывает ветку, название открывает её обзор/статью; наведение само по себе не открывает. Поиск, хлебные крошки, выделение текущего пункта и сохранение позиции предложены как средства навигации, ещё не согласованы отдельно.

Текущая база проверена: 0.53.2. Во вкладке «Об игре» уже есть вводные блоки/вкладки и тексты `description37…65`, `wiki-*` в [index.html](../dist/index.html) / [ui-text.js](../dist/ui-text.js). [mechanics-reference.md](mechanics-reference.md) — короткая действующая техническая справка; [current-model.md](current-model.md) явно исторический, не использовать как текущую модель. Порядок входа/обновления — [контекст](workflows/context.md), код по темам — [навигация](navigation/README.md).

## Предложение устройства

- Один канонический набор небольших глав, из которого собирается браузерное пособие. Не поддерживать вручную копии длинного текста в Markdown, HTML и ui-text. Короткая техническая справка остаётся индексом правил/функций, не второй полной книгой.
- Оглавление, устойчивые адреса разделов, перекрёстные ссылки и «Подробнее» из подсказок/графиков. Краткое объяснение видно сразу, точные детали раскрываются внутри главы. Глубокая ссылка открывает нужную часть «Об игре».
- Реестр: ID главы, темы, файлы/символы реализации, связанные главы и версия последней сверки. Начать с существующей карты; не создавать автоматически большой индекс всех символов.
- У каждой механики объяснять состояние, наблюдения/доступные сведения, момент изменения, расход/результат, связи с соседними механизмами и значение наблюдаемых показателей. Отделять субъективное подкрепление от здоровья/выживания и родительскую наследственность от личного обучения.
- Числа по возможности подставлять из экспортируемых констант; смысл формул сверять с функциями. Планы, неподтверждённые гипотезы и исторические правила не выдавать за текущие.
- Полный текст не передавать агенту при каждой задаче: короткий индекс → одна глава → только её функции/контракт; для связанной правки — соседняя глава. После первоначального обхода весь проект заново не перечитывать.

## Тематические блоки и размер подпатча

1. Основа пособия и навигации, реестр соответствия коду, правила поддержки; полные главы мира, времени/действий, тела/энергии и пищи/среды.
2. Сведения/координаты, память, все блоки мозга, выбор/обучение/стоимость, начальная и наследуемая структура, размножение/геном/мутации/отбор. Добавить схемы причинных цепочек и примеры по подтверждённым функциям.
3. Опыты/seed/попытки, показатели/периоды/веса/незавершённые жизни/ДИ/сравнение, конструктор, сохранения/экспорты, производительность и ограничения. Связать определения показателей с соответствующими главами; сверить покрытие и убрать заменённые дубли текстов.

Каждый блок разбивать на законченные микропатчи по конкретным темам, сверяя соответствующие функции и проверки. Сначала каркас навигации и небольшой законченный вводный раздел, затем пополнение дерева; не объявлять всё пособие полным до покрытия и проверки всех запланированных механик. Это предложение последовательности, не поручение выполнить все блоки. Дефекты статистики сохранены отдельно в [контракте статистики](next-experiment-statistics-ui.md#живое-обновление-и-точность-стоимости-мозга--обсуждение).

## Поддержка и критерий готовности

Новое требование пользователя действует для каждого выпуска: оценить влияние на пособие и обновить затронутые объяснения/ссылки вместе с изменением. Для косметики сверить руководство и отразить применимость в выпуске, не переписывать несвязанные главы ради отметки. Соседние главы учитывать по реестру зависимостей; версию последней содержательной сверки не заменять автоматически во всех главах.

Предлагаемые автоматические проверки: уникальные ID/рабочие ссылки, существующие символы/константы, охват изменённых файлов реестром и явная отметка проверки соответствующих глав. Эти проверки контролируют структуру и дисциплину, но не доказывают смысловую истинность текста; её проверять по затронутому коду. Интерфейс и сборщик пособия выбирать в первом разрешённом патче, без лишних зависимостей/инструментов и без новой работы на подшаг.
