# Локальный рабочий цикл

## Запуск и окружение

Рабочий каталог — корень репозитория. Игра статическая: `python -m http.server 8000 --bind 127.0.0.1 --directory dist`, затем http://127.0.0.1:8000/. Сервер отдаёт файлы, модель считается в браузере; `file://` не заменяет HTTP для модулей/Worker. Перед повторным запуском проверить существующий сервер, не создавать дубликаты.

Для разработки нужны Git, Python и Node; не устанавливать их повторно без проверки. В этой Windows-среде ранее использовались `D:/Programs/anaconda3/python.exe` и `C:/Users/BAZA/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node.exe`. Проверить существование; для дочерних Node-команд добавить его каталог в PATH, установить `PYTHONUTF8=1`. Это локальная подсказка, не обязательный путь для другого компьютера. [verify-local.py](../../tools/verify-local.py) ищет Node также сам.

## Проверки

Короткие исполняемые проверки разрешены пользователем; прежние запреты относились к работе на сайте. Длинные опыты и полные серии замеров без отдельного поручения не запускать. После ошибки исправить и повторить соответствующую часть; без причины не повторять неизменённое.

| Объём | Команда |
| --- | --- |
| Только документы/инструкции | `python tools/verify-local.py --only docs` |
| Синтаксис, DOM, документы, снимки | `python tools/verify-local.py --only static` |
| Инициализация | `python tools/verify-local.py --only startup` |
| Короткие Node/Worker-проверки | `python tools/verify-local.py --only worker` |
| Текущие механизмы | `python tools/verify-local.py --only mechanisms` |
| Полный короткий набор | `python tools/verify-local.py` |

Результат содержит scope и реально выполненные проверки; он не доказывает настоящую браузерную отрисовку или длительную эволюцию. Для оптимизации — эквивалентность и сопоставимые замеры одной серии; для новой модели — правильность механизмов и подходящий снимок/серия. Методику читать в [performance-plan.md](../performance-plan.md), детали проверок — [verification.md](../verification.md).

## Снимок и упаковка

При смене серии прежнюю сохранять в Git и исключать из текущей поставки, не исправляя её расчётные файлы. Для чтения старых отчётов достаточно соответствующих метаданных.

Расчётные снимки неизменяемы; исходный и новый снимки технической оптимизации должны сохранять точные версии. `python tools/freeze-benchmark.py VERSION COMMIT` читает зафиксированный commit и рекурсивные зависимости. Перед этим допускается `python tools/export-source.py --build-only` для метаданных. Изменение модели начинает подходящую новую серию; UI/документы нового снимка не требуют. Старую серию не предлагать в текущих запусках и не объявлять её числа измерением новой модели.

Заключительный проход: актуальная документация → проверки → `python tools/export-source.py` → при нужном готовом пакете `python tools/package-github.py`. Копии/манифест/ZIP напрямую не редактировать. Обсуждение обновляет контракт, а не релизный архив. Корневой `LOCAL-CODEX-START.md`, локальные настройки/логи и секреты не включать в пакет. Старые ссылки source?file при переименовании сохранять через SOURCE_ALIASES в экспортёре; локальные Markdown-ссылки/якоря проверить.

## Публикация

С 21 октября 2026 пользователь дал постоянное поручение: после завершённых и проверенных блоков обновлять существующий [GitHub-репозиторий](https://github.com/Griseus4/big-evolution-model) без повторного согласования. Это заменяет прежнее требование отдельного разрешения для каждого обновления GitHub. Поручение относится к будущим завершённым изменениям; обсуждения без готового изменения не требуют пустого коммита или релиза.

Рабочая цель — `Griseus4/big-evolution-model`, ветка `main`; перед отправкой проверить актуальный адрес, ветку и удалённые изменения. При проверке этого поручения репозиторий доступен через GitHub-коннектор, но у локального checkout нет настроенного remote. Это не основание создавать новый репозиторий: использовать существующий доступ/проверенную настройку. Не переписывать удалённую историю; при несовпадающих историях готовить перенос в отдельном checkout от актуальной удалённой ветки, сохраняя местные незавершённые изменения.

Законченный блок: подходящие проверки → актуальная документация/производные файлы → коммит относящихся к работе файлов → отправка → проверка удалённого коммита. Если изменены ресурсы dist, [GitHub Pages workflow](../../.github/workflows/pages.yml) запускает публикацию сайта при push в main. Проверить результат workflow и отдельно сообщать, если он ещё выполняется/завершился ошибкой; локальный коммит не равен обновлённому репозиторию или работающему сайту. Не включать локальные логи, пользовательские файлы и посторонние незавершённые изменения.

Sites и другой хостинг требуют отдельного поручения. Если поручен Sites, использовать актуальный Sites skill, прочитать `.openai/hosting.json` для существующего проекта и получить текущий доступ через get_site. Сохранить действующую аудиторию и список доступа; не создавать второй Site и не заменять доступ старой записью/режимом только владельца. Учётные данные и письма посетителей не записывать в репозиторий; разрешения проверяет сервис. Исторический маршрут переноса — не новая авторизация публикации.
