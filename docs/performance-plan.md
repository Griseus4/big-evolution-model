Период пищи 20/50, поэтому не приписывать разницу оптимизации. Оценка 50–54%, TD 23–27%, память около 16% подробного времени. UI около 1–2% общего времени.

## Реализовано 0.20

[Постоянная серия](updates/v020-fixed-benchmarks.md): три оценочных нагрузки по 4096 пакетов и три мира по 64 вызова шага, прогрев и три повтора из одного снимка. Один Worker, без отрисовки и конкурирующих запусков. computeMs исключает подготовку/копирование/хеши/проверки/уступки; wallMs показывает расписание отдельно. Медиана/разброс, проверка начальных/итоговых отпечатков и числа действий, локальный JSON/сравнение. Это база для следующих обновлений, не доказательство выигрыша относительно 0.19.

Малый технический блок: neuralInputs/actionFeatures переиспользуют найденную запись и belief внутри текущего вызова. Нет долговечного кэша, изменения частот/точности/физики. 125 пользовательских проверок подготовлены; агент их не запускает.

## Как продолжать

1. Получить JSON проверок и постоянных замеров ПК; телефон держать отдельной серией.
2. Повторить тот же набор на том же устройстве. Если разброс сравним с выигрышем, повторить измерение и проверить нагрузку/температуру.
3. Следующий небольшой блок выбирать по сопоставимому профилю: оставшиеся выделения/общие вычисления оценщика либо TD/память. Зафиксированные входы pending/панели не должны меняться при повторном использовании буферов.
4. Обычный мир переносить в Worker отдельным этапом при необходимости. Это освобождает интерфейс, но не распараллеливает один мир по 20 потокам автоматически. Потребуются протокол команд/снимков, ограниченная частота обмена и проверка детерминизма.
5. Новые механизмы и оптимизацию чередовать небольшими блоками. Не оптимизировать гипотетические растения/драки до выбора их модели.

Перед реализацией оценивать объём обходов, выделений памяти, копирования и сообщений на шаг/жителя, масштаб до 1000. Сразу убрать очевидную лишнюю работу, сохранить понятность. Сложные кэши/параллелизм обосновывать замерами. Не сокращать наблюдения/обучение и не подменять алгоритм ради красивого числа скорости. Правило закреплено в [AGENTS.md](../AGENTS.md) и [START_HERE.md](START_HERE.md).
