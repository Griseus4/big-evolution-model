# Полный снимок мира для продолжения опыта

Реализовано в0.36.0: [формат, границы и проверки](updates/v036-environment-energy-save.md). Следующий текст сохраняет исходный контракт и причины решения; описание ограничений0.35.1 является историческим.

18 октября2026. Пользователь утвердил ручное сохранение полного мира в файл и загрузку с точным продолжением в ближайшем патче0.36, включая жителей/память/обучение/текущие действия/RNG/автоматическую среду. Автоматические сохранения остаются отдельным этапом. Ниже контракт и план реализации; работающая версия0.35.1 ещё не умеет загружать полный мир, игровой код не менялся.

## Что есть сейчас

`Evolution.snapshot()` в [evolution.js](../dist/evolution.js) предназначен для сравнения запусков в проверках. Он содержит жителей, мозги, записи памяти, часть RNG/настроек/истории/календаря; это не готовый полный формат сохранения с загрузчиком. Например, явно не перечислены начальные величины балансов, nextId, лимит/все настройки, subtick/ready state, полноценный наблюдатель пищевого интеграла/историй. Простого JSON.stringify недостаточно: типизированные массивы и Maps нужно явно кодировать/восстанавливать. Личные состояния параллельного расчёта принадлежат вычислителям; перед снимком требуется согласованная синхронизация. [Пул](../dist/parallel-world.js) уже имеет syncAll после завершённого шага, что даёт часть инфраструктуры.

Экспорты генома/lives остаются отдельными форматами. По seed воспроизводится начало, а не текущие опыт/тела/ход процесса. Старый lives JSON не превращается в savegame.

## Утверждённый объём первого этапа

Кнопки «Сохранить мир» (файл) и «Загрузить мир» (выбор файла). Самостоятельный именованный формат/версия и версия модели. На первом этапе гарантировать загрузку своего поддерживаемого формата; перенос через произвольные будущие изменения модели не обещать.

Сохранять карту/источники/лежащую пищу/календари, настройки, точное время/идентификаторы, всех живых и их процессы, геномы/личные веса/следы/память/подкрепление/оперативное внимание, состояния всех RNG, сценарий среды/его RNG/стадию/опоры/следующее событие, родословные/сохранённые истории/счётчики/пищевой интеграл/начальные балансы. Восстанавливаемые индексы/рабочие буферы не сериализовать как обязательную истину; пересоздавать после валидации. Обрезанную ещё до сохранения историческую детализацию восстановить нельзя.

Снимок получать на согласованной границе после полного шага и синхронизации владельцев мозгов. Загрузка в паузе; до замены текущего мира полностью проверить данные и готовность нового мира/пула. Ошибка/отмена выбора файла оставляют нынешний мир целым. Число вычислителей — настройка исполнения, не обязательная часть биологического состояния.

Автоматическая контрольная точка перед первым обеднением полезна, но способ хранения пока не выбран: файл по кнопке либо отдельное долговременное хранилище браузера; простая копия в оперативной памяти не переживает закрытие страницы. Не скачивать файлы каждые1000 Т и не копировать весь мир на каждом подшаге. Автосохранение/квота/число точек — отдельный контракт, в первый вариант предложены надёжные ручные сохранение/загрузка.

## Проверяемый результат

МирA проходитN шагов → save → ещёM шагов. МирB загружается из save → проходитM шагов. При одинаковой модели и дальнейших вмешательствах совпадают биологическое состояние, обучение/память, все RNG, действия/календари/автоизменения и наблюдательная статистика. Повторить с одним/несколькими вычислителями и сменой числа владельцев после загрузки. Не сравнивать реальные миллисекунды/визуальный кэш.

Проверить порождённые ID после загрузки, текущие роды/сбор, половину усвоения/следующий рост, все стадии среды, пустой мир, повреждённые/неподдерживаемые файлы, типы/диапазоны/ссылки. Крупные сохранения оценить по фактическим памяти/времени отдельно; это потенциально самая затратная часть предлагаемого выпуска, не обещать мгновенность.
