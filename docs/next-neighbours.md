# Восприятие соседей — 0.25

## Реализовано

- Круговой обзор радиуса 1: своя клетка и шесть соседних, за краем карты клеток нет.
- По каждой видимой клетке известно количество **других живых** особей. Себя не считает.
- На своей клетке доступны стабильные ID текущих участников через `Evolution.contacts`. На соседних клетках — только количества.
- Нет социальной памяти, узнавания прежней встречи, отношений, наблюдения чужого действия/здоровья/родства, новых действий или наград за общение.
- ID не числовой признак сети. Список контактов строится по запросу панели, не копируется для всех жителей при каждом проходе мозга.
- Обзор актуален на момент решения в последовательном порядке мира: уже переместившийся, родившийся или умерший меняет видимость сразу.
- `Evolution.neighbours` возвращает только локальные q/r, номера относительных направлений и количества. Индекс мировых клеток в мозг не передаётся.

## Новая сеть и совместимость

Новый случайный опыт: геном v8, `mlp-neighbours-v1`, 35 → 16 tanh → Q, 593 параметра + 13 свойств = 606 чисел. Первые 32 входа имеют прежний смысл; три новых — другие на своей клетке, в клетке рассматриваемого действия, во всём обзоре. Для действия без шага клетка варианта — своя.

Количество n кодируется как n/(n+1). Это плавное насыщение, не ограничение точного счётчика. Сеть не получает готового знака предпочтения и может выучить притяжение, избегание или отсутствие реакции. Наличие признаков не гарантирует стаю.

Сохранённый v7 остаётся 32 → 16 → Q / 558 чисел и игнорирует соседей. Автоматического расширения нет: это выбранный пользователем способ совместимости. v1–v6 сохраняют таблицу. Сравнение анализатора между v7/v8 — только 13 общих свойств; сдвинутые веса не объявляются одинаковыми генами.

## Стоимость и проверки

`neighbour-perception.js` поддерживает Map клетки → Set ID и Map ID → клетка. Добавление, удаление и перемещение — O(1) в среднем; локальный обзор — семь запросов, без обхода всего населения. Индекс — производные данные мира, не наследуемая память. `rebuildOccupancy` нужен после прямой расстановки тел в фикстуре; обычная игра обновляет индекс по событиям.

Подготовлены 15 проверок: количества, границы, приватность, контакты, движение, рождения/смерти, локальная симметрия, входы и реакция сети, градиент всех 593 параметров, продолжение TD, совместимость v7/v8, наследование, восстановление индекса и сверка с независимым подсчётом после шагов. Агент их не запускал. Пользователь запускает «Испытания → Проверка механизмов» и присылает JSON.

Производительность новой модели измеряется в отдельной серии `neural-neighbours-v1`, нагрузки `fixed-neighbour-workloads-v1`. Старые серии сохранены в Git, их отчёты можно прочитать, но нельзя сравнивать с новой моделью как оптимизацию.
