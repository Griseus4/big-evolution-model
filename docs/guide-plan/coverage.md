# Реестр охвата: исходная точка P00

Статус: структурная инвентаризация выполнена для приложения 0.54.8. Исходная опубликованная ревизия — `0aa90ead28a0697a0d3df8383a74db4bf214709d`; рабочая папка содержит давно накопленный diff относительно локального Git, поэтому отдельные файлы дополнительно закреплены SHA-256. Это не новая содержательная сверка механик.

Документы этой серии (`docs/guide-plan/*.md`) учитываются одной служебной группой: план, карточки и этот реестр. Их назначение проверено в P00; точность описания приложения они сами по себе не доказывают. Добавляемый файл назначать теме в соответствующей таблице, пересчитывать весь реестр автоматически не требуется.

## Метод и поля

Список получен через `rg --files --hidden` с исключением Git, локальной .transfer, настроек агента и node_modules. Сверен с dist/project-guide-inventory.json и правилами tools/guide_inventory.py. За пределами автоинвентаря отдельно учтены корневые HTML/скрипты запуска, фикстура JSON, документы, конфигурации и производные данные. Никакие файлы не удалены.

В таблицах: источник и отпечаток; этап/ответственность; статья-вход; основание и символы из sources/checks. Общий статус «не проверено» и отсутствие новой содержательной сверки указаны перед каждой таблицей. Плановая статья не означает уже созданный подробный раздел. Для большой функции закрывать ответственность по отдельности, а не весь файл сразу.

При завершении главы добавить вопрос/раздел статьи, существенную границу, реальную проверку, оставшийся пробел и проверенную версию в её строку или отдельную строку ответственности. Статус «частично» сохранять, пока у файла остаются непроверенные обязанности. Перенесённые из метаданных reviewedVersion ниже — прежние отметки, не результат P00.

## Условия продолжения

P00 завершён структурно: рабочие файлы имеют маршрут, статьи и прежние отметки сопоставлены, исключения обоснованы. Содержательная полнота ещё не достигнута; процент полноты не вычисляется по числу файлов/ссылок. После P00 пользователь разрешил всю серию; повторные разрешения между этапами не требуются.
