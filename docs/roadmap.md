# Дорожная карта Big Evolution

Обновлено 2026-10-14. Цель задана пользователем; порядок ниже — предложение,
не разрешение реализовать все механизмы. История выпусков — в [updates](updates/README.md).

## Ближайшая цель

Наблюдать эволюцию от отдельных особей к устойчивой группе, в перспективе —
стае с вожаком. Память и личное обучение сохранить: способности мозга важнее
локальной экономии вычислений. Среда и отбор создают условия для поведения,
готовые команды «собраться в стаю»/«назначить вожака» не вводятся.

Ориентир пользователя — около двух часов на ПК для содержательного эксперимента;
интересное наблюдение может длиться дольше. Прежний предел полчаса снят 04:22.
Это бюджет удобства, не гарантия стаи на каждом seed или фиксированное число шагов.
Один продолжающийся мир остаётся сценарием. Допустимы последовательные опыты:
сначала жизнеспособные основы с нуля, затем новый опыт на одном/нескольких
сохранённых геномах. Импорт одной основы существует; набор основ/интерфейс этапов
пока предложение. Геном не переносит личную память и приобретённые поправки.

## Сейчас

Исходники 0.27. Геном v9 с индивидуальной изменчивостью; мозг 35→16→Q (v7 сохранён без расширения), личное Expected SARSA, короткая/долгая память.
Есть карта 48×32, источники еды, ручное изменение источников без перезапуска,
добровольное рождение, выкладывание еды и анализ генома. Существа воспринимают количества соседей и текущие ID на своей клетке; социальные действия, стаи, бой, мясо, хищники,
автоматическая сезонность и живые растения не реализованы.

183 механизма подготовлены, JSON выполнения текущего выпуска не получен.
585 замеров 0.24 разобраны: оценщики быстрее 0.22, миры 150/400 медленнее,
мир1000 быстрее. [Результаты](updates/v024-shared-repeats-and-results.md),
[варианты оптимизации и условия выбора](optimization-options.md).
Оптимизация — средство обеспечить бюджет опыта. По решению 04:22 крупная
оптимизация отложена; развиваем содержание, сохраняя модульность и предотвращая
очевидные лишние расходы. Восприятие — [контракт соседей](next-neighbours.md), новая пища/след — [0.27](updates/v027-food-islands-and-trail.md).
Текущее распознавание ID на своей клетке реализовано; социальная память и взаимодействия отложены.

## Предлагаемая последовательность

| Этап | Наблюдаемый результат и ограничения |
| --- | --- |
| Поддерживать достаточную скорость | Крупная оптимизация отложена. Предотвращать лишние обходы/копирование, сохранять измерители и границы модулей. Возвращаться к профилю при неудобной длительности опыта. |
| Восприятие соседей | Локальные сведения о присутствии/плотности; позже различение видимых особей. Индекс по клеткам вместо обхода всей популяции на каждый взгляд. Скопление у еды само по себе не стая. |
| Простые взаимодействия | Добровольные социальные действия: удары и/или передача пищи отдельными блоками. Реальные боль/энергия/последствия, визуальная отметка; без автоматической мести/премии за убийство. |
| Экологический смысл группы | Условия, в которых совместное пребывание/действие может помогать: угрозы, обмен полезными сведениями, помощь. Не гарантировать, что группирование выгодно всегда. |
| Хищники и пищевые цепочки | Мясо/трупы/гниение и различные тела постепенно. Выход мяса связан с телом/энергией смерти, не фиксированной наградой за убийство. |
| Разнообразная среда | Автоматическое изменение условий, разные районы и увеличение карты по потребности опыта. Растения как эволюционирующие организмы — отдельный более поздний слой. |
| Анализ групп/влияния | Устойчивость совместного движения и взаимодействий, кто влияет на направление группы. Звание «вожак» описывает обнаруженное поведение, не создаёт его. |

Драки сами по себе могут вести к избеганию соседей. Нужна возможная польза
социального поведения, которую житель воспринимает и может выучить.
Для лидерства одного счётчика плотности недостаточно: потребуется наблюдать
поступки соседей, а необходимость личной социальной памяти определить отдельно.

## Границы изменений

Контроллер мозга уже отделён от мира; схема входов/генома, память, география,
пища и UI имеют отдельные модули. Часть исполнения действий остаётся в Evolution.
При развитии выделять новые взаимодействия в модули и сохранять явные границы:
наблюдения → оценки/обучение → исполнение → последствия → история/UI.
Не делать общую переделку проекта ради предполагаемых будущих возможностей.
Новое действие всё равно требует связей с восприятием, мозгом, историями и проверками;
это нормальная интеграция. Изменение входов/выходов — отдельная версия модели.

Ручное управление, дети/два родителя, строительство/технологии, долголетие,
биомы и desktop остаются [идеями](future-ideas.md), не обязательной лестницей.
Стая с вожаком — ближайший исследовательский ориентир, не потолок игры.
Каждый этап проверяет механизм, а эволюционный исход может быть разным.
