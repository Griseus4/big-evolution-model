# 0.27 — индивидуальные островки и след выбранного жителя

## Согласованный результат

Пользователь утвердил островки с собственными размерами, периодами и фазами,
ручное число основных островков и общие настройки распределения. Общее число
источников сохраняется. Одиночные кусты остаются; кисть и редактирование строк
отложены. След хранит 20 перемещений только выбранной особи, начиная с выбора.

## Пищевые правила

- Общее число источников 0…384, по умолчанию 384; основное число островков
  1…384, по умолчанию 8. Реально не больше числа источников, при нуле групп нет.
- Одиночные кусты: минимум из floor(N×0.2) и N−min(запрошенные островки,N).
  Поэтому при достаточном бюджете около 20% источников отдельные; при запросе
  множества групп сначала уменьшается доля кустов. Куст — группа из одной клетки
  со своим расписанием, не дополнительная пища сверх бюджета.
- Размер означает количество источников. Положительные случайные веса
  1±разброс/100 распределяют бюджет после выделения кустов. Наибольшие остатки
  дают точную целую сумму, минимум один источник в каждой группе. Разброс весов
  не является строгим диапазоном итоговых размеров после нормировки/округления.
- Центральный период 10…1600, по умолчанию 20; разбросы размеров/периодов
  0…90%, по умолчанию 30%. Период = round(центр×(1+U[-1,1]×разброс/100)),
  затем ограничивается 10…1600. Это центральное значение распределения, не
  гарантированная медиана небольшой выборки и не единый таймер.
- Фаза целая 0…period−1; 0 даёт первое событие через полный период,
  остальные — через phase шагов от начала цикла. Первый срок равномерно
  распределён между 1 и period. Затем события через period шагов.
- Каждый неполный источник группы получает одну порцию на событии.
  Полные/переполненные пропускают его без долга. Ёмкости случайные 3…6;
  при старте заполнены. Кусты выбираются на свободной суше с предпочтением
  расстояния от центров, но не обязаны быть изолированы от всех соседних растений.
- Одни seed/настройки/вмешательства повторяют раскладку. Пищевые RNG отдельные;
  гены и стартовые позиции не подгоняются под пищу. Центры/таймеры/фазы не входят
  во входы мозга; геном v9, сеть 35→16→Q и формулы обучения прежние.

## Продолжающийся мир и наблюдения

Поля стартовых условий, текущего мира и длинных испытаний имеют одинаковый смысл.
Изменение числа источников/островков, разброса размеров или явная перестановка
пересоздаёт размещение. Изменение только центрального периода/его разброса
сохраняет места. При любом фактическом изменении расписания формируются от шага
вмешательства; применение совпадающих условий сохраняет цикл и журнал.

Все лежащие порции сохраняются на своих клетках. У новых источников нет
дополнительного запаса; еда на бывшем источнике остаётся доступной без роста.
Ёмкости сохраняются как случайный набор прежних источников, добавленным задаются
3…6. В UI убрана одинаковая ёмкость; исторический API/проверки сохраняют прежнее
поведение через individualFood:false и старый sourceCapacity.

Панель показывает фактическое число групп/кустов, размеры и диапазон периодов.
Наведение на источник показывает группу, период и фазу наблюдателю.
Наблюдения содержат начальные/текущие группы и расписания, журнал вмешательств
хранит независимую копию групп. Длинные задания/сводки сохраняют все параметры.
Это аналитический экспорт, не сохранение полного мира для продолжения.

## След

resident-trail.js живёт только в интерфейсе основного мира. После выбора —
начальная точка, после успешного перемещения — следующая. 21 точка образует
максимум 20 отрезков. События движения записываются между кадрами, поэтому
ускорение не пропускает повороты. Ожидание/еда/рождение не стирают маршрут.
Повторный клик той же особи сохраняет след. Другой выбор/новый мир сбрасывает;
смерть оставляет последний маршрут. След не экспортируется и не учит мозг.

## Стоимость и границы

Раскладка/сортировки выполняются при генерации/вмешательстве. Расстояния центров
обновляются за O(суша×число островков), без повторного обхода всех прежних центров.
На шаге проверяются группы, а источники читаются только у плодоносящих групп;
нет обхода всей карты/населения для роста. След хранит максимум 21 точку одной
жизни; Workers его не создают. Геном/TD/память не переделаны.

0.27 меняет модель мира: серия neural-food-islands-v1, нагрузки
fixed-food-island-workloads-v1, новый исходный снимок 0.27.0. Снимок 0.26
остаётся в Git, исключён из текущего сайта; межсерийное сравнение не доказывает
оптимизацию. Профиль скорости и старые JSON остаются читаемыми.

## Проверки пользователя

183 механизма подготовлены; 8 новых в food-island-checks.js, 5 в
resident-trail-checks.js. Исторические проверки синхронного роста явно используют
individualFood:false. Агент выполняет только статические проверки/упаковку.

1. «Испытания → Проверки механизмов» → запуск → скачать весь отчёт.
2. На карте выбрать жителя: след начинается сейчас, сохраняется при ожидании,
   содержит повороты при ускорении; смена жителя очищает. После смерти остаётся.
3. В стартовых условиях попробовать 8 и 16 островков при одинаковых 384
   источниках. Число источников остаётся 384, средняя группа уменьшается.
4. В текущем мире изменить только период: порции и места сохраняются.
   Изменить число островков: места меняются, порции остаются на старых клетках.
   Повторное применение без изменений не сбрасывает цикл. При нуле источников
   нет следующего пополнения, остатки доступны.
5. Для наблюдения разных расписаний можно поставить центр 100, разброс 30%,
   8 островков и затем наблюдать. Миграция/выживание не обязательны. Скачанный
   JSON позволяет проверить параметры; отсутствие миграции само по себе не баг.

Браузерные клики/отрисовка, исполнение механизмов и скорость не подтверждены
статической проверкой. Результаты ожидаются от пользователя.
