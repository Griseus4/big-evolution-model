# 0.45.0 — компактные архивы опытов и частичная загрузка

Статус: реализовано локально. [Контракт и исходные измерения](../next-experiment-storage.md). Физика, геномы, RNG, обучение и статистические формулы прежние; изменяется хранение и чтение наблюдений. Публикация не выполнялась.

## Для пользователя

«Опыты → Запуски → Скачать результаты опытов» по умолчанию сохраняет один `.beexp`. В выборе формата остаётся обычный JSON. Можно открыть `.beexp`, прежний JSON отчёта и `.json.gz`. CSV не нужен для работы приложения. Планы/геномы/полные сохранения мира остаются отдельными форматами.

Все поля жизней, попытки, вымирания, метаданные и исходная точность сохраняются. 12 диагностических полей не удалены. После просмотра части опыта архивный экспорт сохраняет все блоки, а не только открытое окно. Обычный JSON и экспорт наблюдений при необходимости восстанавливают полные данные.

Архив проверяется до замены текущего опыта. Ошибка/отмена выбора сохраняют прежний источник статистики. В браузерной базе завершённые попытки теперь хранятся компактными Blob; старые записи-объекты остаются читаемыми. Блоки и оглавление серии фиксируются одной транзакцией. Ошибка записи не помечает попытку успешно сохранённой.

## Формат и стоимость

`experiment-archive.js` — владелец формата. 16-байтный префикс `BEXPAR01` хранит длины сжатого/исходного оглавления. Оглавление gzip содержит версию, метаданные, общие схемы и смещения независимых блоков. Жизни разделены по миру/попытке, dead/living, 500 Т рождения и не более 512 строк в блоке. Таблицы хранят пути полей один раз, постоянные значения отдельно, переменные — строками. Пропуск поля не равен null. Позиции возвращают прежний порядок строк; повторный экспорт копирует сжатые блоки без декодирования жизней.

При импорте все блоки проверяются последовательно, без удержания всех строк. Для графиков декодируются только блоки выбранных попыток, пересекающие общий период рождения и независимый период кривой дожития. Узкое окно внутри уже прочитанного отбирается без повторной распаковки. Остальные поля жизни доступны в прежних анализаторах; статистический код не читает индексы колонок напрямую. У каждого отчёта один последний кэш окна, без неограниченного накопления периодов.

Вспомогательный блок мира содержит полный ряд событий населения, возраста завершённых жизней для неизменной сводки заголовка и пищевые ряды. Они нужны даже при частичной загрузке рождений. Их размер зависит от всей истории выбранного мира; это не выборочное чтение каждого столбца. Полный период по-прежнему требует все соответствующие жизни. Подготовка выборок метрик остаётся в JS; ДИ в существующих Workers, число перевыборок не меняется.

Ограничения: файл до 2 ГиБ, оглавление/отдельный распакованный блок до 64 МиБ, суммарный объявленный объём блоков до 8 ГиБ. Старый JSON сначала целиком читается/разбирается, затем переводится в архив: уменьшение пикового RAM его первого импорта не заявляется. Большие plain JSON могут упереться в предел строки/памяти браузера раньше файлового лимита. Архив нового формата поддерживается с этого выпуска; старый клиент его не понимает. Сжатие требует CompressionStream/DecompressionStream. Это собственный контейнер приложения, не ZIP/CSV/база SQL.

## Проверки и измерения

277/277 Node-тестов, 44/44 механизма, запуск и статические проверки прошли. Проверены точное восстановление данных, пропуски полей, Unicode/null, повреждённые блоки, JSON/gzip, частичные окна и повторный экспорт полного отчёта. Совпадение выборок проверено отдельно от скорости их подготовки. Эти результаты относятся к выпуску 0.45.0; они не подтверждают последующие изменения автоматически.

В браузере обнаружено, что прежний guard пары принимал короткое загруженное окно за отсутствие подробностей исходного отчёта. Теперь `incompleteLifeHistory` отличает размер окна от полного числа сохранённых смертей; настоящий omittedDetails по-прежнему исключает неполные данные. Проверены полные пары и временные B−A против исходных полных отчётов. Формулы оценок/перевыборок не менялись.

Chrome в отдельном профиле: два настоящих мира по 1 Т, компактные попытки в IndexedDB, скачивание .beexp и JSON, повторный импорт, синтетический опыт десяти миров с разными рождениями, общий период 500–1000 Т и независимая кривая 1000–1100 Т, пять полных пар с ДИ после частичного чтения, полный повторный экспорт и открытие браузерного архива после перезагрузки. Ширины 1440/460 px, без горизонтального переполнения; исключений JS нет, снимки просмотрены. Отчёт `.transfer/v045-browser-verification.json`; это не длинный эволюционный опыт.

На прежнем `big-evolution-experiment-2026-10-19T16-22-36-249Z.json` (20 групп, 21 попытка, модель 0.39.2) измерено: 259 843 002 → 29 803 702 байта (примерно 8,72 раза). Восстановлены и точно сопоставлены все поля всех 185 692 жизней и попыток, данные не удалялись. Создание архива в Node около 10,7 с; полная проверка около 4,9 с. Это не новый отчёт 40 миров и не браузерный замер.

Для окна 10 000–11 000 Т плюс кривой 0–100 Т у 20 итоговых миров: 9 912 загруженных жизней вместо 177 942, прочитано 60 из 1 284 блоков строк. Подготовка 25 показателей (медиана пяти повторов): 744,5 мс на полных данных против 39,1 мс на загруженном окне; холодное чтение окна около 308,7 мс. Исходные выборки всех 25 показателей точно совпали. Эти величины не являются ускорением симуляции или полной отрисовки/ДИ. Скрипт и результат: `.transfer/measure-storage045.mjs`, `.transfer/storage045-real-analysis.json`.
