# 0.22 — Облегчённая оценка продолжения для TD

2026-10-13. Реализовано по разрешению пользователя продолжить оптимизацию согласно обсуждённому плану. Агент выполняет только статические проверки; механические проверки и замер пользователь запускает на своём устройстве. Выигрыш и эквивалентность исполнения новой версии ещё не подтверждены пользовательским отчётом.

## Почему этот участок

В начале шага после наблюдения и закрепления памяти обучение запрашивало подробные варианты через Evolution.evaluate. Они содержали собственные input/features/senses, итоговые объекты, мировые назначения и затем ещё объекты nextValues. Последствие использовало только сумму probability × learningValue. Прежние профили показывали значительную стоимость оценки, но не измеряли отдельно долю выделения памяти. Выигрыш именно от устранения этих объектов — проверяемая гипотеза.

Новый путь: learnPending → expectedContinuation → decisionFrame(a,false) → expectedControllerValue → expectedNeuralValue → finishControllerOutcome(nextValue). Физическая доступность и порядок кандидатов прежние; запрос строится тем же методом. Компактный frame не создаёт Map/копии назначений исполнения. Мировые координаты, как и раньше, остаются только в физике.

## Скалярный расчёт

Сеть по-прежнему получает 32 входа и выдаёт Q через 16 tanh. Для каждого кандидата заполняется один частный input; Q/score складываются в небольшие буферы. Расчёт точно сохраняет последовательность: score = Q / 0.35; peak = max(score); weight = exp(score−peak); sum слева направо; затем expected += (weight/sum) × Q в порядке кандидатов. Деление не переносится за суммирование, ожидаемое значение не заменяется максимумом.

Не создаются подробные объекты оценки/исполнения, отдельные input/features/senses для каждого кандидата и массив объектов nextValues. Writer fillNeuralInputs полностью перезаписывает входы/признаки; fillActionFeatures записывает те же девять признаков. bodySenses допускает заданный буфер, обычный вызов возвращает свежую пару как прежде. Одна запись памяти/belief на кандидата сохранена. При выключенной памяти используется частный неизменяемый нулевой потенциал без построения соседей для памяти.

Буферы продолжения живут в прежнем WeakMap и создаются лениво на первом таком вызове. Input32/features9/senses2 — 43 слота обычных числовых Array; values11/weights11 — 22 Float64 (176 байт), плюс объекты/заголовки. Обычный Array для input сохраняет тип входов горячего neuralValue, вместо добавления второго типа Float64Array к публичным/градиентным входам. Фактический размер JS-массивов зависит от движка; фиксированную суммарную цену в байтах не объявляем. Прежние типизированные parameters/hidden/gradient занимают 8848 байт данных. Дополнение не требуется, если обучение не вызывает этот путь. Рабочие буферы не наследуются, не экспортируются, не входят в снимок жителя; ссылки на них не покидают скалярный расчёт.

Эффективные параметры base+delta собираются перед каждым пакетом. Нет межвызовного кэша оценок или версии весов. Входы/число кандидатов всегда заново заполняются; уменьшение пакета не читает хвост старого буфера.

## Сохранённые границы

Публичные evaluate/evaluateFrame/choose по-прежнему возвращают полные варианты с отдельными историческими массивами. Pending копирует выбранные входы и не ссылается на рабочий input. Табличные геномы используют прежний подробный адаптер для расчёта вероятностей, затем свёртку в число. Старый вызов finishControllerOutcome с nextValues поддерживается; новый nextValue=0 не вызывает запасной reduce. Терминал получает ноль, без оценки будущего; выключенное TD тоже не вызывает продолжение.

Закрепление памяти выполняется перед оценкой продолжения; TD затем обновляет веса; выбор действия получает новую полную оценку уже после TD. Эти две разные оценки не объединены. Геном v7/558, формула обучения/градиент/след, физика, цены действий, частоты наблюдения, порядок RNG и способы выбора не изменены намеренно; точное исполнение проверяет пользователь.

Профилировщик оборачивает expectedContinuation той же группой evaluation. Его время вычитается из родительского learning, как прежняя оценка evaluateFrame. Поэтому смена пути не изображает ускорение переименованием затрат.

## Проверки

Добавлено шесть пользовательских проверок, теперь всего 133:

- Полные входы/ощущения/признаки сравниваются с независимой формулой 0.21, включая -0, крайние значения, все действия, риск, давность и отключение памяти. Перед заполнением буферы содержат NaN, чтобы обнаружить неперезаписанные поля.
- Expected Q сравнивается с прежним прямым проходом/softmax при смене памяти, TD, параметров и размера пакета 11/1/5/2/0.
- Частные буферы не переписывают подробные варианты/pending или другой мозг; старый и новый контракты завершения TD с нулевой оценкой совпадают.
- Компактный request равен публичному, RNG не расходуется; терминал/TD-off не оценивают будущее.
- Полные миры совпадают с прежним подробным путём по snapshot/RNG при разных режимах и старом мозге. Синтетический пожилой основатель и сильная склонность другого к рождению обеспечивают охват терминала/потомства. Это тестовые фикстуры, не изменения обычных основателей.
- Фиктивные часы подтверждают прежнюю классификацию оценки/TD и восстановление метода измерителя.

Замороженный neural-v018-reference.js не изменён; его прежние проверки чисел, TD и миров сохранены. Определения новой независимой формулы и прежнего пути — continuation-checks.js.

## Как измерить на ПК

1. Обновить страницу, «Испытания» → «Проверки механизмов», запустить 133 проверки.
2. «Замеры скорости»: загрузить предыдущий JSON 0.20/0.21 (отдельный или общий), затем выполнить постоянный замер на том же устройстве/браузере.
3. Скачать верхней кнопкой общий JSON и прислать его. При ошибках сначала разбираем правильность, затем скорость.

Серия fixed-neural-workloads-v1 и её шесть нагрузок не менялись. Три изолированных случая измеряют публичный подробный оценщик, а не новый скалярный путь; они помогают заметить регрессию общего writer. Основной ожидаемый эффект проверять в трёх полноценных мирах, где есть TD. Их короткие 64 шага не доказывают устойчивость эволюции и обычно не охватывают рождения; рождения проверяются отдельной регрессией.

Первый пользовательский замер 0.20 имел разброс около 2.5–11.1%. Если выигрыш сравним с разбросом, повторить запуск. Изменившиеся стартовые/итоговые отпечатки или число действий делают сравнение несопоставимым. Процент ускорения до этих данных не объявлен.

Статическая подготовка: синтаксис/импорты 46 JS-модулей, 190 HTML ID и 246 локальных ссылок проверены. Импорт определений подтверждает 0.22.0, 133 проверки, прежнюю серию v1 без выполнения миров/проверок. Код фиксированных нагрузок/runner/state и замороженный эталон 0.18 не менялись. Архив исходников пересобирается перед публикацией; выполнение новой версии и коэффициент ускорения не объявлены проверенными.
